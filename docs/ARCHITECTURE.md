# MovieBox Pro TV 0.3 — architecture and contracts

This is the build contract for the TizenBrew module. Every source file, test and tool follows it. If code and this document disagree, fix one of them in the same change.

## 1. Goals, in priority order

1. **Reliable for years.** It never leaves the TV stuck. Every site-dependent step has a fallback, and every failure is logged and recoverable with the remote.
2. **Search works.** Remote typing, live suggestions, real results in a TV grid, type tabs and paging. It never depends on the page's own search form.
3. **Premium 10-foot UI.** It should feel like Apple TV+ or Netflix, not a website overlay.
4. **Plays through the website's own endpoints.** The built-in player (`docs/PLAYER.md`) uses exactly what the website's player uses (the title page's file list, `tv_file`, the player data and the progress posts); the website's own player stays as the fallback. No stream scraping and no private APIs beyond what the website itself calls.
5. **Smooth on TV hardware.** TV performance mode (§6.4) trades decoration for frame rate on TVs.

## 2. Runtime environment facts (verified 2026-09-24)

- TizenBrew runs the site in its own Tizen web-app window and injects `tv.js`. With `evaluateScriptOnDocumentStart: false` it calls CDP `Runtime.evaluate` on **every** `Runtime.executionContextCreated`. The script can therefore run:
  - before `document.documentElement` or `document.body` exists (cached, fast evaluation);
  - more than once per page (isolated worlds or extension contexts), sharing one DOM but **not** JS globals;
  - in iframes, where it must exit immediately.
- The script is fetched from `https://cdn.jsdelivr.net/gh/AHcoder23/moviebox-pro-tv@<ref>/tv.js` and cached in memory until TizenBrew restarts.
- Samsung browsers range from Chromium 47 (Tizen 3, 2017) to Chromium 120+. **Runtime code must be ES5.** See §9 for banned APIs and CSS.
- The website (`https://www.movieboxpro.app/`, also served on the apex host) is a jQuery 1.7 PHP site. Without a login every page is the "Private Garden" gate. The site sniffs Samsung user agents and uses JW Player for them.
- Remote keys: arrows 37–40, OK 13, Back 10009 (Esc 27 on desktop), Play 415, Pause 19, Play/Pause 10252, Stop 413, FF 417, RW 412, Red 403, Green 404, Yellow 405, Blue 406, Info 457, Ch+ 427, Ch− 428, digits 48–57. Media and colour keys must be registered with `tizen.tvinputdevice.registerKey` in a try/catch.

JSON endpoints (same-origin GET, cookies included):
- `/index/search/autocomplate?q=Q&limit=12` returns `[{"name": "..."}]`. It does not record history. Use it for live suggestions.
- `/index/api/search_hot` returns `{code:1,data:{list:[trending strings], html:"<div class=search_history>... <p class=search_submit key=K data-id=N>K<img></p>..."}}`. Parse `data.html` with DOMParser and read `[key]` for recent searches.

Playback URLs (the website itself implements these):
- Movie: `/movie/ID?play=1` clicks `.start_app` once the page is ready. With one source the player starts; with several, `.sidebarbg2` opens.
- Episode: `/tvshow/ID?season=S&episode=E&play=1` clicks that episode.
- Show "resume": `/tvshow/ID?play=1`.

Loading a movie or TV page does **not** record watch history (verified), so detail prefetching is safe. Playback does.

Artwork (verified 2026-09-24): posters and stills come from the thumbnail service `https://thumb.chuaxin.com/thumb_<B64>.png`, where B64 is URL-safe base64 (`-` and `_`, no `=` padding) of `<path>|<width>|<quality>`, for example `uploadimg/movie/2026/09/20/2026092019330165235.jpg|500|74`. The service honours any width (300, 500, 780 and 1280 all return images of exactly that width in about 0.2 s); the site itself uses 500 px posters and 300 px episode stills. The original file is `https://images.chuaxin.com/<path>`. Backdrops are TMDB `image.tmdb.org/t/p/original/…`, used at `/t/p/w1280/` (`w780` in performance mode).

## 5. Data contracts

### 5.1 Item (a title card)

```js
{
  key: 'movie:40102',          // kind + ':' + id — stable identity
  kind: 'movie' | 'tv',
  id: '40102',
  title: 'The Batman',
  href: 'https://www.movieboxpro.app/movie/40102',   // absolute, same-origin, no query
  poster: 'https://thumb.chuaxin.com/thumb_...png', // '' if none; never a /static/ placeholder
  backdrop: '',                // landscape art when known (home banners, detail cache)
  rating: '7.8',               // '' if missing or '0'
  tomato: '85%',               // ''
  year: '2022',                // ''
  runtime: '176 min',          // ''
  genres: ['Action', 'Crime'], // title-cased, may be []
  badge: '4K' | 'Blu-ray' | '',
  update: 'S05 E13',           // latest-episode label for shows, ''
  progress: 0.0625,            // 0..1 for continue-watching cards, else -1
  progressLabel: 'S37E21',     // or '01:02:09', ''
  playHref: 'https://.../movie/1831?play=1'  // continue/play link when the page provides one, else ''
}
```

### 5.2 `Site` API (src/10-site.js). Pure functions; `doc` is any Document (live or DOMParser-made).

- `Site.parseTitleUrl(str, base)` returns `{kind, id, season, episode, play}` or `null`. It accepts `/movie/ID`, `/tvshow/ID`, `/index/index/detail?id=ID` (movie), `/index/index/tvdetail?id=ID` (tv), relative or absolute, same host only (either host variant: www or apex), and ignores `from=`.
- `Site.targetOf(el)` returns the title URL from `href`, `data-link`, `data-href` or an `onclick` of the form `(window.)location.href='...'` (quotes of either kind, `&amp;` decoded), or `''`.
- `Site.cards(root, opts)` is the **generic extractor**: every element whose `targetOf` parses as a title becomes a card. The card root is the nearest ancestor (or self) that contains artwork without containing a different title. Fields are filled per §5.1. Dedupe by key, keeping the richest record. Works without layout (DOMParser docs); when `opts.live`, drop hidden cards.
- `Site.home(doc)` returns `{rows: [Row], banners: [{key, kind, id, href, image}]}`, where `Row = {id, title, items: [Item], more: url|''}`. Rows come from `.section h3` (strip the "More" link text). The fallback is one row from `Site.cards(doc)`. Banner images also fill `backdrop` on matching items.
- `Site.list(doc)` returns `{title, items, next: url|'', chips: [{label, href}]}`.
- `Site.search(doc)` returns `{query, type, total: number|null, types: [{type, label, href, selected}], items, playlists: [{title, href, image, count}], next: url|'', empty: bool}`.
- `Site.detail(doc, url)` returns `null` or:

```js
{ kind, id, key, href, title, year, poster, backdrop /* TMDB w1280 variant */, backdropOriginal,
  runtime: '176 min', certification: 'PG-13', genres: [], update: 'Update to S05 E13',
  ratings: {imdb: '7.8', tomato: '85%', audience: '87%'},   // '' when missing or '-,-%'
  overview, badges: ['4K HDR', '4K', 'Blu-ray'], audio: 'ENG', playLabel: 'PLAY',
  sources: [{index, quality: '4K'|'1080p'|'720p'|'SD'|'Original', file, size, date}],
  cast: [{name, role, image}], related: [Item],
  season: 2, seasons: [{number, href, current}],
  episodes: [{season, episode, code: 'S2E1', title, date, runtime, overview, still, rating, watched}],
  allEpisodes: {1: [{season: 1, episode: 0, code: 'S1E0', title: 'Building the Batman', watched: false}, ...], 2: [...]},
  seasonStats: {1: {watched: 13, total: 14, label: 'Season 1 · 93%'}, ...},
  nextEpisode: {season: 2, episode: 1, code: 'S2E1', resume: false} | null }
```

  For shows, `allEpisodes` and `seasonStats` come from the watch-plan list (§3), for every season. `episodes` is the season's `.tv_episode` cards plus every episode only that list names (for example an S01E00 special) as a name-only entry (`still`, `date`, `runtime`, `overview` and `rating` empty), sorted by episode number; every episode carries `watched`. `seasonStats` takes the site's own "N/M episodes watched" line when there is one (else it counts the list), and `label` is the "Season 1 · 93%" line. With no season pills in the markup, `seasons` comes from the list. `nextEpisode` is the episode a show-level Play starts: an "S2E3"-style resume label on the page's Play button (`resume: true`), else the first unwatched episode (seasons and episodes from 1: a special is never picked on its own), else the first episode; `null` when the page has no watch-plan list (the App then decides, see docs/PLAYER.md). Movies have `{}`, `{}` and `null`.
- `Site.thumb(url, width, quality)` returns the same thumbnail at another width (quality defaults to 80), re-encoded URL-safe without padding, keeping any query. `Site.original(url)` returns `https://images.chuaxin.com/<path>`. A thumbnail is recognised by its file name `thumb_<B64>.(png|jpg|webp)` plus a payload that decodes to exactly `path|width[|quality]`, so the host may change (the offline mock serves them from `/__img/thumb/`); any other URL, and any input that does not decode, comes back unchanged.

- `Site.isGate(doc)` returns true for the "Private Garden" gate: a `.login_btn` or `/index/login` link, with no nav and no `.contents`.
- `Site.pageType(locationLike, doc)` returns one of `home | search | list | library | movie | tv | gate | login | other`.
- `Site.url` builds absolute same-origin URLs: `search(q, type, page)`, `title(kind, id, season)`, `play(kind, id, season, episode)`, `home()`, `movies()`, `shows()`, `library()`.
- `Site.live` holds live-DOM helpers, used only on the real page: `playButton()`, `episodeButton(season, episode)`, `sourceItems()` (visible `.sidebarbg2 li.play`), `sourcePickerOpen()`, `closeSourcePicker()`, `playerOpen(ctx)`, `closePlayer(ctx)`, `playerContainer()`, `video()`, `blockingPopups()` (visible `.not_support_bg`, `.vip_pay_tips`, `.player_bg`, `.no_resource_bg`, `.season_bg`) and `dismissPopup(el)` (click its close control, else hide it).
  - `playerOpen(ctx)`: `#my_dialog` is visible, **or** a visible `video` covers at least 40% of the viewport and counts. Videos inside visible same-origin iframes count too. A video counts when it sits inside a known player container (`#my_dialog`, `#player_box`, `#player_panel`, `.jwplayer`, `.jw-wrapper`, `.video-js`, directly or through its iframe). A video outside them counts only when `ctx.current` is that video (the one player mode drives), or when `ctx.recent` is set (a play action is pending or happened in the last 15 s) and the video is neither looping nor a muted-autoplay element (both are attribute checks, so a hero trailer is never the player; JW Player falls back to muted autoplay by setting the property, which still counts).
  - `video()` returns the largest visible video inside a player container, else the largest visible video. `playerContainer()` returns the visible dialog, or the container (or iframe) around the player's video, or `null`.
  - `closePlayer(ctx)` clicks `#dialog_close`, and if the player is still open it pauses every video (except the built-in player's, inside `#mbptv`) and hides `#my_dialog`. It returns whether the player is gone.
  - Videos inside our own root `#mbptv` (the built-in player's `<video>`) are never the website's player: `playerOpen`, `video()` and `playerContainer()` ignore them.
  - Hiding a site element (`closeSourcePicker`, `dismissPopup`) sets `display: none` and, when a site `!important` rule still wins, `display: none !important` inline; the site's next `show()` replaces it.
- `Site.suggestions(jsonText)` returns `[string]`. `Site.hot(jsonText)` returns `{trending: [string], recent: [string]}`.
- `Site.selfTest(doc, type, parsed?)` returns `{ok, warnings: [string], counts}` for diagnostics. `parsed` is the page's `Site.home` or `Site.detail` model when the caller already has it, so the page is not parsed twice.

Every Site function must be total: it catches internally and returns an empty-but-valid structure, never throws.

### 5.3 `Api` (src/20-api.js)

All callbacks are Node-style `cb(err, result)` and are called exactly once, asynchronously.

- `Api.fetchDoc(url, cb)` uses a same-origin XHR GET with `withCredentials`, a 15 s timeout and one retry on network error or 5xx, then parses with `DOMParser` (falling back to `document.implementation.createHTMLDocument`). If `Site.isGate` is true the error is `{code: 'signed-out'}`. It returns `{doc, url: responseURL || url}`. Identical in-flight requests are shared.
- `Api.fetchJSON(url, cb)`.
- `Api.home(cb)`, `Api.list(url, cb)`, `Api.search(q, type, page, cb)` (fetches the search page and runs `Site.search`), `Api.suggest(q, cb)` (autocomplete; the caller debounces by 350 ms, and stale responses are dropped by sequence number), `Api.hot(cb)`.
- `Api.detail(kind, id, cb, opts)` returns the Detail model (`opts.season` asks for that season's page; `opts.force` skips the memory cache and replaces it). `Api.cached(kind, id, season?)` synchronously returns a Detail already in memory, or `null`; it never fetches. Results are cached in memory (50) and a compact metadata copy goes into localStorage `mbptv:meta:v1` (LRU 300 entries, 14-day TTL, fields: title, year, backdrop, poster, runtime, certification, genres, ratings, overview ≤ 420 chars). `Api.meta(key)` synchronously returns cached metadata or null. `Api.prefetch(item)` is low priority, holds at most one request in flight, and a newer prefetch replaces an older one.
- `Prefs`: `get(name)` and `set(name, value)` on localStorage `mbptv:prefs:v1`. Defaults: `{quality: 'best', nativeRemote: true, nativePlayer: true, autoplayEpisodes: true, reduceMotion: false, performance: 'auto'}`; `quality` is one of `'ask'|'best'|'1080p'|'720p'`, `performance` one of `'auto'|'on'|'off'`, the others are booleans. The retired `autoplayNext` (stored as `false` by older versions on every TV where a setting changed) is ignored when read and dropped on the next write. For a generic Settings row: `Prefs.describe(name)` returns `{key, label, desc, value, valueLabel, toggle, choices}` (or `null`), `Prefs.choices(name)` returns `[{value, label}]` in display order (a toggle is `[On, Off]`; `choices()` without a name still returns the quality values), `Prefs.label(name, value)` the display label, and `Prefs.next(name)` moves a choice or toggle to its next value (wrapping) and returns it. Labels: `nativePlayer` "Built-in player", `autoplayEpisodes` "Autoplay next episode", `performance` "TV performance mode" (Auto / On / Off).
- `Session` (sessionStorage `mbptv:session:v1`): `save(stack, {expect, returnTo})` before any navigation away (defaults: the current page type and URL), `take(pageType)` on boot returns the saved stack once (valid for 30 min and only if the page type matches `expect`; a non-matching page leaves it for the page that matches). Also `peek()`, `returnTo()` and `clear()`. `touch()` resets the saved record's time (App calls it about once a minute while playback is starting or playing, so the way back survives a long film).
- Additions used by the UI: `Api.prefetch(item, cb?)` (cb once: the Detail, `null` when already cached, or `{code:'superseded'}`), `Api.remember(detail)` (seed the caches from the live page), `Api.onSignedOut(fn)`, `Api.cancelSuggest()`, `Prefs.onChange(fn)`. Superseded `Api.suggest` callbacks are never called (the one exception to "exactly once").
- `Api.recentSearches()` and `Api.addRecentSearch(q)` keep a local list of 12 alongside the server's history. `Api.clearRecentSearches()` empties it (Settings > Clear search history, and on sign-out).

Storage wrappers must survive `localStorage` throwing (Tizen private mode, quota) and fall back to memory. `Store` keeps every value this page wrote in memory and reads it back first, so a failed (full) write never returns an older stored value.

## 6. UX specification

Reference frame: 1920×1080. `#mbptv { font-size: 0.8333vw }`, so **1em = 16px at 1080p**. All sizes use `em`, never `rem` (the site sets the html font size).

### 6.1 Visual system

- Colours: bg `#07070a`; elevated `#131318`; elevated-2 `#1c1c23`; hairline `rgba(255,255,255,.08)`; text `#f5f5f7`; text-2 `rgba(245,245,247,.72)`; text-3 `rgba(245,245,247,.6)` (secondary text that is still read: counts, hints, roles, notes, card subtitles, episode meta); brand gold `#e7bd68`; IMDb chip `#f5c518` with black text; fresh `#fa320a`; success `#35c46a`.
- Type: `"SamsungOne", "Samsung Sans", "TizenSans", "Helvetica Neue", Helvetica, Arial, sans-serif`. Display 4.5em/800 (hero title), H1 3em/700, section 1.75em/600, body 1.5em/400 (24px minimum for reading text), meta 1.25em/500, micro 1.0625em/600 in caps with letter-spacing .06em (badges only). Nothing that is read is smaller than the meta size (1.25em, 20px); card badges use the micro size.
- Safe area: 3.5em top, 5em right, 3em bottom. Content starts at left 9em (rail collapsed).
- Surfaces use no borders; depth comes from tone and shadow. Radius: cards .5em, buttons 2em (pill), sheets 1em.
- Focus is unmistakable at 3 m. Cards scale 1.08 with a `0 0 0 .22em #fff` ring and a `0 1.2em 2.4em rgba(0,0,0,.6)` shadow, and their titles brighten. Buttons, chips, keys and list rows (suggestions, settings, log lines) turn solid white with black text; list rows also scale 1.02. At rest the primary button is a brighter translucent pill than the others, never white, so only the focused control is white. Motion: `transform .18s cubic-bezier(.2,.8,.2,1)`. Everything is still with `reduceMotion`. A new screen fades in from 40% opacity, never from black. Cards are not promoted to their own compositing layer at rest (a card is promoted only while it animates).
- No emoji (Tizen fonts lack them). Icons are inline SVG with `fill="currentColor"`.
- Images fade in (opacity .25s; at once in performance mode). Placeholder cards show an elevated tone with the title text centred, so a missing poster still looks deliberate.
- Images go through `Kit.img(url, {cls, parent, w, fallback, eager})` (the older `Kit.img(url, cls, parent, fallback)` still works). `w` is the width it is shown at (CSS px at 1080p): `Kit.imgUrl(url, w)` asks the site's thumbnail service for that width (`Site.thumb(url, w)`, when the adapter has it; any width works) and maps TMDB art to `w780`/`w1280` (never a larger file than it came as); performance mode caps widths at 780. A sized picture that fails falls back once to the original URL, then to `fallback`, then to the placeholder. Cards ask for 500 px posters and 780 px landscape art (300/342 and 500 in performance mode, `Kit.cardWidth`); full-screen art uses `Kit.backdrop(url)` (1280, or 780). Lazy images load within one viewport of the screen; in performance mode within half a viewport, nearest first, at most 6 at a time (a load that never ends frees its slot after 10 s). `Kit.loadNow` (hero and backdrop art) skips the queue.

### 6.3 Navigation model

- `App` keeps a stack of `{screen, params, focusKey, scroll}`. Back pops (screens may handle Back first: Search returns to its keyboard, Home returns to its first row); an empty stack on Home opens the exit dialog.
- Screens render from **fetched** documents (`Api.*`), so moving around the catalogue never reloads the page. The one exception: when the boot page itself is the needed page (for example boot on `/` for Home, or on `/movie/ID` for that detail), it uses the live DOM directly.
- **Play** (`App.play(t)`): the built-in player first (`playNative`, docs/PLAYER.md "Integration"). It plays in place, over the current screen, with no page load: a show-level Play/Resume resolves its episode first (the explicit one, else the Continue Watching label, else the title page's `nextEpisode` (its resume label, else the first unwatched episode), else an "S2E3"-style label on its Play button, else the first episode of the season the title page shows, else S1E1), and `quality: 'ask'` with several files opens the quality sheet first. The title page is the one on screen, the boot page or one already in memory (`Api.cached`); when none is known (for example the Play key on a show's card on Home), it is read first behind the "Starting playback" overlay (Back cancels; after 6 s playback starts with what is known). Back (or the end of a movie or last episode) closes it onto the screen it opened from, with focus on the control that started it, or on the episode that played last when Up Next moved on; that detail screen shows what was watched at once (§6.2) and, 1.5 s later, re-reads its title page and patches it in place (`refreshModel`; it rebuilds only when it cannot patch, what it shows about progress changed and the viewer has not moved), and Home re-fetches Continue Watching 1.5 s later (rebuilt only when it changed, never under the viewer's hand; My Library screens below rebuild when shown again). The website path below (`playWebsite`) runs when Settings > Built-in player is off, when the built-in player refuses the request, and on its error card's **Try website player**; a signed-out answer routes to sign-in. A `?play=1` page (old links, bookmarks) also plays in the built-in player and drops `play=1` from its URL, unless the website path opened it (sessionStorage `mbptv:webplay:v1`, 60 s); the website's own auto-play on that page is then kept quiet (its file list, player and messages close without showing, and its videos are paused) until the viewer's next website play action.
  1. Website path: if the live page is this title's detail page, click the live control (`Site.live.playButton()` or `episodeButton`).
  2. Otherwise save the stack in `Session` with `returnTo` set to the current URL, set `mbptv:webplay:v1`, then set `location.href = Site.url.play(...)`.
  3. On a `play=1` page the shell boots into a "Starting playback" overlay (backdrop, title and spinner). The source picker or player then takes over. If after 5 s neither `playerOpen()` nor `sourcePickerOpen()` is true, it clicks the live play control itself. If still nothing after 10 s it shows the detail screen with a toast "The website didn't start playback. Try Play again." The 5 s click happens only when the website did not react at all (no picker, player or message) and only on a `?play=1` page; a live click on the title page is never repeated.
  4. When the player closes via Back: if `Session` has `returnTo` and `history.length > 1`, call `history.back()`; the previous page restores its stack from `Session` (or bfcache `pageshow`). Otherwise show the live detail screen.
- Focus engine: every focusable element has `data-f` and lives inside a **zone** element (`data-zone="rail|hero|row:ID|grid|keyboard|tabs|list|sheet|dialog"`). Left/Right inside a `row`/`tabs` zone moves to siblings (Left at index 0 goes to the rail); Up/Down between zones restores the zone's remembered index, clamped to the nearest by x-position; grids navigate by column; anything else uses geometric nearest-in-direction within the active layer. The topmost layer (dialog > sheet > screen) owns input. Scrolling uses CSS transforms on the zone track (horizontal) and on the screen body (vertical), never `scrollIntoView`.
- Key repeat: honour auto-repeat but render at most one focus move per animation frame; seek repeats accelerate. A held OK or Back acts once: repeated keydowns (`KeyboardEvent.repeat`, or no keyup in between, expiring 700 ms after the last keydown so a lost keyup never disables a key) and keyup/keydown pairs less than 25 ms apart (how some TVs report auto-repeat) are swallowed. Arrows, seeking, and OK on the search keyboard's letters and Delete keep auto-repeat. Grids (`[data-zone="grid"]`) navigate by index and column from a cached list: Right stops at the row end, Down from a column past the end of a shorter last row goes to the last card.

### 6.4 TV performance mode

`Prefs.performance` is `'auto'` (default), `'on'` or `'off'`; auto is on when the user agent matches `Tizen|SMART-TV|Web0S|NetCast` or `window.tizen` exists (`Kit.perf()`). While it is on, `#mbptv` has class `mb-perf` (set by `App.applyPrefs`, which follows `Prefs.onChange`), and:
- no blurred box-shadows on cards, buttons, chips, keys, sheets, dialogs, toasts or the player's pills: focus keeps the white ring (a spread-only shadow) and scales less (cards 1.05, buttons and chips 1.04);
- no opacity crossfades on large layers: hero and backdrop art, row fades, the detail dim and header, the rail's gradient and width, the screen fade-in, layer dims, and the built-in player's art, OSD and Up Next scrim swap at once (the hero text fades in .1 s);
- no endless decorative animations (the search caret does not blink, skeletons do not shimmer); spinners still turn;
- smaller pictures and fewer loads at once (§6.1), TMDB backdrops at `w780` instead of `w1280`;
- screens use `Kit.timing(name)` for calmer timings: `dwell` (the hero's detail prefetch) is 700 ms instead of 450 ms.

## 7. Reliability requirements

- **Boot guard**: wait (poll every 30 ms up to 20 s, plus `DOMContentLoaded` and `readystatechange`) until `document.body` exists. Exit if `window.top !== window.self`. Exit if `document.getElementById('mbptv')` or `documentElement[data-mbptv]` already exists (an injection in another world). Run on a `movieboxpro.<tld>` host (www or apex) or the configured start host. Never run on third-party login hosts (Google, Apple, Facebook, Microsoft, Twitter/X). Any other host (a moved domain, the offline mock) runs only with the site's own signature and never on a page with a password field: `#top_nav_home`, the "Private Garden" gate (`.login_btn` plus a `/index/login/qrcode` or `/index/login/code_login` link), or a page title that ends with the site name ("… - MovieBoxPro"). The title is the usual signal, because only the head is certain to be parsed when the check runs.
- **Error isolation**: every event handler and timer callback is wrapped with `U.guard(fn, label)`, which catches, logs and continues. If a screen render throws, show the fallback screen for that route ("Couldn't load this page" with **Retry** / **Open website** / **Home**). If the shell itself fails to boot, remove it entirely and leave the website usable. The website must never be left covered by a broken overlay.
- **Watchdog**: every 2 s, if the shell is in a visible mode but has no focused element, or the focused element is detached, re-focus the screen's default element. If the player is detected while the shell is visible, switch to player mode. While the built-in player is up it only re-applies the `<html>` classes (no focus repair, no website-player checks).
- **Network**: every request has a timeout, a retry and a user-visible outcome. A signed-out response routes to the sign-in screen.
- **Adapters degrade**: primary selectors first, then the generic `Site.cards`. Empty results show an empty state with **Open website**, never a blank screen. `Site.selfTest` warnings go to `Log`.
- **No site JS globals**: interact only through the DOM (clicks, events), URLs and same-origin HTTP, because the module may run in an isolated world. Never call `jQuery`, `jwplayer` or `init_player`.
- **Security**: never inject HTML strings built from site data. Use `textContent` and attribute setters (the lint checks the syntax tree for `innerHTML`/`outerHTML` assignments, `insertAdjacentHTML`, `document.write`, event-handler or computed `setAttribute` names and `javascript:` strings). Only same-origin URLs are navigated to: same scheme, host (www or apex) and port as the live page, and navigation sinks assign the URL rebuilt onto the live origin (`U.onOrigin`), never a raw URL from site markup. Only `http(s)` images from any host are displayed. There is no `eval` or `new Function`.
- **Diagnostics**: `Log` holds a ring buffer of 200 entries (time, level, label, message), mirrored to localStorage `mbptv:log:v1` (last 60). Every message is redacted centrally: URL fragments are dropped and query values are masked unless the parameter only names a title or a page (`id`, `season`, `episode`, `play`, `type`, `page`, `limit`, `box_type`), so search words and tokens never reach storage or the Diagnostics screen; entries stored by older versions are redacted when read. The live page's self-test runs 4 s after boot (or when Diagnostics opens), never before the first render, and reuses the page parse made at boot.
- **Remote keys never get lost**: one capture-phase `keydown` listener (and `keyup`, for held keys) on `window`, also added to every same-origin `iframe` window (the website may load its player page into one). The watchdog puts DOM focus back on the `.is-focused` control when anything else (a site input, an ad or embed `iframe`) holds it, and blurs a focused cross-origin `iframe` in every mode. Key handlers that throw 4 times in 15 s switch to website mode; if that also fails, the shell removes itself.
- **Playback never traps the viewer**: Back during "Starting playback" cancels, and for 4 s afterwards a website player that still opens is closed again; a website picker the viewer closed stays closed (it is hidden again whenever it reappears) until the next play action. Back while the `?play=1` page is still loading stops that navigation (`window.stop()`) and leaves a marker (sessionStorage `mbptv:cancel:v1`, 15 s) so the play page, should it load anyway, never starts playback and goes back. After the viewer closes or cancels playback, a website player that is still on the page (it could not be closed, or it is paused behind the shell) only brings player mode back when it really plays again (its time moves), until the next play action. Blue or Info on a site popup returns to the TV app and ignores that popup until the next play action; Back on a popup that cannot be hidden does the same with a toast. A message that answers a Play (no files, VIP only, not ready) ends that attempt when dismissed and is repeated as a toast. A `?play=1` page the viewer stays on (playback ended, failed or was cancelled) drops `play=1` from its URL with `history.replaceState`, so a reload or a later Back into it never starts playback again. If the website's file list cannot be read (markup changed), the website's own picker is shown with the focus ring (popup mode) instead of being covered. If the website's player uses browser fullscreen, the OSD moves inside the fullscreen element. While playback starts or plays, the saved `Session` record is refreshed about once a minute (`Session.touch`).
- **The page behind the shell never scrolls**: in boot, shell and player modes `html.mbptv-lock` sets `overflow: hidden` on `<html>` and `<body>` (and removes the page scrollbar); website and popup modes leave the page scrollable. `Boot.teardown` (and so a panic) removes every `mbptv-*` class from `<html>` and `<body>`, resets a scroll lock, removes our nodes and stylesheet, and stops every App timer and listener.
- **Privacy on shared TVs**: signing out (or booting on the gate) forgets the local recent searches and the saved `Session`; the server keeps its own history.
- **Website mode survives page loads** (sessionStorage `mbptv:web:v1` = `{t, origin, kind}`, 30 min): `kind: 'here'` (Settings, Open website view) keeps website view while the viewer browses the site; `kind: 'nav'` (Open website on a screen) returns to the shell when the viewer comes back to `origin`. Leaving a page in website mode saves the shell stack to `Session`, so Blue / the TV pill restores the viewer's place. Back in website mode takes one history step at a time: a second Back within 2.5 s while the first is still loading is ignored. A page restored from the back-forward cache re-applies these rules on `pageshow` (the `nav` marker for this page is dropped, `here` restores website view) and resets in-flight guards.
- **No unbounded growth**: every cache is capped (screens kept: 4, detail memory 50, metadata 300, suggestions 40, URL resolvers 24, log 200), and grids stop paging at 600 titles.

## 9. Banned in runtime code

JS: `=>`, `let`, `const`, `class`, template literals, spread/rest, destructuring, default params, `async`/`await`, `Promise` (avoid; use callbacks), `fetch`, `Object.assign`, `Array.from`, `Array.prototype.includes`/`find`/`findIndex`, `String.prototype.includes`/`startsWith`/`endsWith`/`repeat`/`padStart`, `NodeList.prototype.forEach`, `Element.closest` (write `U.closest`), `Element.prototype.append`/`prepend`/`remove` (use `removeChild`), `classList.toggle(x, force)` second arg, `IntersectionObserver` without a fallback, `requestIdleCallback`, `URL`/`URLSearchParams` (parse with an `<a>` element), `Symbol`, `Map`/`Set`, optional chaining, `??`, `Object.values`/`entries`/`fromEntries`, `.at()`, `.flat()`/`.flatMap()`, `.trimStart()`/`.trimEnd()`, `.replaceAll()`, `.padEnd()`, `.findLast()`, `Node.isConnected`, `getAttributeNames`, `structuredClone`, `queueMicrotask`, `globalThis`, `AbortController`, `ResizeObserver`, `scrollIntoView`, event constructors (`new Event(...)`; use `document.createEvent`), and the site's globals (`jQuery`, `$`, `jwplayer`, `init_player`). `KeyboardEvent.key` is missing before Chromium 51: read `keyCode` first (`Keys.name` does). `U.qs`/`U.qsa` with a missing root return `null`/`[]`; pass `document` explicitly.

CSS: `var(`, `gap:` on flex (use margins), `display: grid`, `inset:`, `position: sticky`, `backdrop-filter`, `filter: blur`, `aspect-ratio`, `:focus-visible`, `:is(`, `:where(`, `clamp(`, `min(`, `max(`, `@supports`. `-webkit-line-clamp` with `display:-webkit-box` is allowed.

## 10. DOM contract for tests and diagnostics

The UI must expose these hooks; `test/app.test.cjs` depends on them.

- Root `div#mbptv` (the only top-level element we add besides `style#mbptv-css`, `#mbptv-pill`, `#mbptv-ring` and `#mbptv-osd`). Attributes: `data-screen` = `loading | home | search | detail | browse | settings | diagnostics | signin | error | native | player`; `data-layer` = `'' | sheet | dialog`.
- The focused control has class `is-focused` **and** is `document.activeElement` (call `.focus()` on it; every focusable has `tabindex="-1"`).
- Title cards: `[data-key="movie:40102"]`. Rows: `[data-zone="row:<rowId>"]`. Grids: `[data-zone="grid"]`.
- Buttons: `[data-action]`, for example `play`, `details`, `episodes`, `quality`, `search-submit`, `retry`, `open-website`, `exit`, `stay`, `nav-home`, `nav-search`, `nav-movies`, `nav-shows`, `nav-library`, `nav-settings`, `season-retry` (Try again on a season that failed to load).
- Keyboard: letter and digit keys `[data-char="a"]` (lowercase), special keys `[data-action="space" | "delete" | "clear"]`. Query text: `#mbptv-query`.
- Suggestions `[data-suggestion]`, recent/trending chips `[data-query]`, type tabs `[data-type="all|movie|tv"]`.
- Episodes `[data-episode="2x1"]` (focus key `ep|2x1`); seasons `[data-season="2"]`. Episode cards have `.is-watched` when watched (its `.mb-ep-check` shows) and `.mb-episode--text` when the site lists them by name only (no `<img>`); the Continue Watching episode has `.mb-ep-progress`. The season line is `.mb-season-info`; `[data-zone="row:episodes"]` has `.is-loading` (and a visible `.mb-ep-spinner`) while a season loads. The detail screen instance exposes `model()`, `refreshModel(detail)` (updates the Play label, watched marks, progress bars and season line in place; false when it cannot), `season()` (the season on screen) and `afterPlayback()` (applies `params.lastPlayed`, which App sets when the built-in player closes: `{kind, season, episode, time, duration, over, resume, marks: {'2x1': 1}, t}`).
- Source picker rows `[data-source-index="0"]` inside `[data-sheet="sources"]`.
- Dialogs `[data-dialog="exit"]`. Toast `#mbptv-toast` (its textContent is the message). Player OSD `#mbptv-osd` (class `is-visible` while shown).
- `window.__mbptv` is set by Boot: `{version, App, Site, Api, Log, U}`; `App.nativePlayer()` returns the built-in player (`info()`, `configure()`) for diagnostics and tests. `App.state()` returns `{screen, stack: [screen names], focusKey, mode: 'boot'|'shell'|'native'|'popup'|'player', layer}`.
- Also exposed: `#mbptv[data-overlay="starting"]` while the "Starting playback" overlay shows; the quality sheet `[data-sheet="quality"]` with `[data-option="best|1080p|720p|ask"]` rows and, on a movie, `[data-file-index]` rows for its files; the error screen's `[data-action="home"]`; settings rows `[data-action="setting-<key>"]` (`quality`, `nativePlayer`, `autoplayEpisodes`, `performance`, `nativeRemote`, `reduceMotion`, `clearSearches`, `diagnostics`, `website`, `reload`, `about`); the built-in player's DOM (`#mbptv-player[data-state]`, docs/PLAYER.md); `#mbptv.mb-perf` while TV performance mode is on; diagnostics `[data-action="selftest"]` and `[data-action="clear-log"]`; `html.mbptv-sources` while our source sheet (or the quiet automatic choice) covers the website's picker; `html.mbptv-lock` in boot, shell and player modes; `html.mbptv-player` in player mode; `html.mbptv-jwctl` while the player controls mode (Blue in the player) shows the website player's controls.
- sessionStorage keys besides `mbptv:session:v1`: `mbptv:web:v1` (website mode across page loads, §7), `mbptv:pick:v1` (a one-time file choice from the quality sheet, consumed by the next source picker for that title within 10 minutes), `mbptv:cancel:v1` (`{url, t}`: the viewer cancelled Play while that `?play=1` page was loading, §7; 15 s), and `mbptv:webplay:v1` (`{url, t}`: the website path opened that `?play=1` page, so it plays with the website's player, not the built-in one; 60 s).
